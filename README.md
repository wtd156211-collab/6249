# 构建缓存与失效传播（从 0 实现）

## 范围

要做的是一个只用 Python 3.13 标准库的命令行判定器 `cache_judge.py`：读入「构建图」和「历史缓存记录 + 两轮之间的变更集」，算出本轮每个目标要不要重跑、为什么，并把失效沿依赖边传到下游。它面对的是一段已经发生的历史，所以不读工作区里的真实文件、不执行动作、不写回记录；同一份输入必须给出逐字节相同的输出。

明确不做：不执行动作，不产生或删除输出文件，也不修补历史记录；不把时间戳（mtime/ctime/atime）、inode、文件大小单独当成「变了」的证据，大小只作为记录里的信息；键和判定结果里不得出现绝对路径、机器名、用户名、环境变量、随机数、当前时间；不做分布式缓存、不远程拉取、不访问网络；不校验目标自己的输出文件在工作区里的存在性和内容，输出指纹只在被下游引用时使用；不做并行、不做缓存清理、不做动作调度。

## 口径与公式

路径一律是仓库根相对路径，`/` 分隔，大小写敏感，UTF-8；路径与参数里不得出现换行。文件指纹 `F(p)` 形如 `sha256:<64 位小写十六进制>`，等于文件内容字节的 SHA-256，文件缺失记作 `-`。

目标 T 的输出集合指纹 `O(T)`，前像按 `path` 升序、每行以 `\n` 收尾：

```
cache-outputs/1
output <path> <F(path)>
```

缓存键 `K(T)` 的前像：

```
cache-key/1
target <目标名>
tool <工具标识>
arg <下标，从 0 起> <参数值>
input <路径> <F(path)>
dep <依赖目标名> <O(依赖)>
```

其中 `arg` 按动作声明的顺序，`input` 按路径升序，`dep` 按依赖目标名升序；`K = sha256(前像)`，同样写成 `sha256:<hex>`。

键只由三样东西决定：声明输入的文件内容、动作参数（连同工具标识）、依赖目标的输出指纹。它不含自身输出，也不含时间戳和绝对路径，所以仓库放在哪里、什么时候判定都不影响结果。依赖一旦要重跑，它的新输出指纹无法预知，此时下游的键不可信，只能跟着重跑。

## 状态机与数据结构

每个目标一轮只判定一次，结果只有三种：`rerun`（必须重跑，给一个原因）、`up-to-date`（记录可复用，原因列写 `-`）、`dropped`（历史里有记录、当前图里已经没有这个目标，记录作废且本轮不重跑，原因列写 `not-in-graph`）。

`rerun` 的原因按优先级取第一条命中的；括号里要写具体项，候选多于一个时取 UTF-8 字节序最小的那个：

| 优先级 | 原因 | 触发条件 |
| --- | --- | --- |
| 1 | `no-record` | 历史里没有该目标的记录 |
| 2 | `corrupt-record(<字段>)` | 字段非法：`key` 不是指纹格式、`tool` 非字符串、`args` 不是字符串列表、`inputs`/`deps`/`outputs` 结构或指纹非法、`outputs` 为空；字段名取字典序最小者。损坏记录按「无记录」退回，不得拿来算下游的键 |
| 3 | `input-missing(<路径>)` | 声明输入在变更集里被删除 |
| 4 | `input-changed(<路径>)` | 声明输入的最新内容指纹与记录不一致，或记录里没登记这个输入 |
| 5 | `args-changed` | 图里的参数与记录不一致 |
| 6 | `tool-changed` | 图里的工具标识与记录不一致 |
| 7 | `dep-rerun(<目标名>)` | 有依赖本轮判定为 `rerun` |
| 8 | `dep-output-changed(<目标名>)` | 依赖本轮可复用，但它的输出集合指纹与记录里登记的对不上，含依赖的输出被变更集改写、删除，或记录里缺这条依赖 |
| 9 | `key-mismatch` | 以上都不成立，但记录里的 `key` 与拿记录自身分量重算的键不同，即记录自相矛盾 |

## 输入输出与文件格式

图文件：

```json
{"version": 1, "name": "diamond", "targets": [
  {"name": "build/left.b", "tool": "cc", "args": ["-O2"],
   "inputs": ["src/left.c"], "deps": ["build/core.a"], "outputs": ["build/left.b"]}]}
```

`targets` 里每一项就是一条动作声明：`tool` 和 `args` 描述动作，`inputs` 与 `outputs` 描述它读写哪些文件。图里 `name` 唯一，三个列表都允许为空；同一个路径不能被两个目标声明为输出；`deps` 只能指向图里的目标且不能成环，依赖关系是失效传播的唯一通道。

历史文件：

```json
{"version": 1, "records": [
  {"target": "build/left.b", "key": "sha256:…", "tool": "cc", "args": ["-O2"],
   "inputs": [{"path": "src/left.c", "fingerprint": "sha256:…", "size": 128}],
   "deps": [{"target": "build/core.a", "output_fingerprint": "sha256:…"}],
   "outputs": [{"path": "build/left.b", "fingerprint": "sha256:…", "size": 4096}]}],
 "changes": [
  {"kind": "write", "path": "src/left.c", "fingerprint": "sha256:…", "size": 141},
  {"kind": "delete", "path": "src/extra.c"}]}
```

`changes` 按发生先后排列，同一路径以最后一条为准；变更既可能落在声明输入上，也可能落在某个目标的输出文件上。某条路径的当前内容指纹就是它最后一条相关变更，没有变更则用记录里的值。

判定结果写到 stdout：每个目标一行，由目标名、判定、原因三段组成，段间用制表符分隔，按目标名的 UTF-8 字节序升序，`dropped` 的目标也占一行；最后一行是汇总 `# rerun=<n> up-to-date=<n> dropped=<n>`，重跑集合就是所有 `rerun` 行。命令行是 `python3 cache_judge.py --graph <图文件> --history <历史文件> [--report <html 路径>]`；给了 `--report` 就再写一份自包含 HTML，不引外链资源、SVG 内联，至少画出所有 `rerun` 目标之间的依赖边，版式自定但内容必须与 stdout 一致。输入不可用（JSON 解析失败、图违反约束、顶层 `version` 不支持）时以非 0 退出、错误写到 stderr，且不输出判定行。

## 性能与验收口径

- 单进程、只用标准库；不得使用递归（链长不设上限，验收会用 ≥2000 层的深链，默认递归上限不够用），同一个目标一轮里只判定一次；
- 一轮判定 O(V+E+C+记录条目数)，V 目标数、E 依赖边数、C 变更条数；
- 验收规模 V=20000、E=40000、C=20000 时判定不超过 3 秒，再加 HTML 报告不超过 5 秒（Python 3.13，普通开发机）；
- 输出可复现：同一输入反复运行 stdout 逐字节相同，不受字典遍历顺序、环境变量、时区、当前目录影响；排序与比较按 UTF-8 字节序、大小写敏感。

## 样例说明

`samples/graphs/<名字>.json` 与 `samples/history/<名字>.json` 同名配对，`samples/expected/<名字>.md` 给出该配对的完整标准输出，逐行可核对：

| 样例 | 覆盖 |
| --- | --- |
| deep-chain | 12 层深链，链首输入被改写，失效逐层传到链尾 |
| diamond | 菱形依赖：一条分支重跑、另一条复用、汇合点只报一次 |
| multi-output | 多输出目标；输出文件被外部改写使下游 `dep-output-changed`；新增目标 `no-record` |
| args-change | 只改参数与工具标识，没有任何文件变化 |
| dropped-target | 目标从图里删掉、历史还留着记录 |
| broken-record | 键格式非法、输出指纹缺失、键与自身分量对不上 |
| deleted-input | 声明输入被删除，比内容变化更硬的失效条件 |

`samples/notes.md` 是现场记录：有人改了文件却没想到要重跑依赖它的目标，线上出现了数据错版本。
